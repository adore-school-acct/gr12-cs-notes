# C3.1 - Intro to Pygame

## Pygame

- **pygame:** game development library created by Pete Shinners
- uses graphics library called SDL (Simple DirectMedia Layer)

### Features

- **Display:** Games use display mode; helps control how overall game looks
- **Surface:** Rectangular surface that contains game items
- **Rect:** Object representing rectangle
	- All surfaces are rectangles
	- Helps det. size and position of objs.
	- Helps w/ collision detection
- **Input modules:** modules that help detect user input from keyboard, mouse, or controller
- **Output modules:** numerous ways to send info back to user
	- i.e. `image` module to deal w/ images
- **Utility modules:** extra utilities to make game programming easier
	- i.e. `time`, `draw`, `transform`

## Time

- **frame rate:** speed at which a game repeats (re-draws its image)
	- unit: hertz or FPS
	- <10 FPS: looks choppy
- games need to do 100s of calcs. in less than a s.
- *lag* occurs when a computer isn't able to complete all calculations in given time period
- FPS balanced between fluid motion and computer specs

*Code:*

```py
...
clock = pygame.Clock()
clock.tick(fps)
```

## Space

- **pixel (picture element):** a dot that makes up an overall image of a display
	- made up of 3 smaller subpixels that are red, green, blue
	- acronym: RGB
- each pixel has (x, y) coordinate
- **resolution:** the length and width of a display
	- i.e. 640 x 480 or 1920 x 1080

```py
...
screen = pygame.display.set_mode((width, height))
```

### Pygame Coordinate System

- X-coordinate is positive to the right
- Y-coordinate is positive downwards
- **origin:** upper-left corner of display
- done like this because it is more efficient for GPU

## Gaming Loop

- **gaming / animation loop:** an infinite loop where the code of the game runs, frame-by-frame
- **resources:** the data involved in a game
	- i.e. game objects, artwork, music

*Basic Steps*

1. Creating / loading most of the **resources**
2. Creating a **gaming loop** where we:
	1. Control frame rate
	2. Get keyboard, mouse, joystick input from user
	3. Update positions of each game object
	4. Refresh screen

## IDEA/ALTER Framework

*Basic skeleton code:*

```py
# I - Import and Initialize
import pygame 
pygame.init()

# D - Display configuration

screen = pygame.display.set_mode((640, 480))
pygame.display.set_caption("Hello, world!") 

# E - Entities (just background for now)

background = pygame.Surface(screen.get_size())
background.fill((0, 0, 255)) 

# A - Action (broken into ALTER steps) 

# A - Assign values to key variables
clock = pygame.time.Clock()
keepGoing = True
# L - Loop 

while keepGoing:
	# T - Timer to set frame rate
	# E - Event handling
	for event in pygame.event.get():
		if event.type == pygame.QUIT:
			keepGoing = False
	# R - Refresh display
	screen.blit(background, (0, 0))
	pygame.display.flip()
```

*Gives blue screen*

- **I - Import and Initialize**
	- `import pygame`
	- Initialize game using `pygame.init()`
- **D - Display**
	- `pygame.display.set_mode((x, y))` initializes game w/ a resolution of `x*y`
	- 640 x 480 is a good resolution for speed and looking at code
	- `pygame.display.set_caption(str)` sets titlebar to display `str`
- **E - Entities**
	- **entities:** game objects *(move around, crash, ...)*
	- background is also entity
	- **surface:** place in memory that represents 2D image
	- `screen` instantiates `Surface` to repr. background
	- Images take time to convert, do them before main loop
	- `fill((r, g, b)` fills screen w/ given RGB values
- **A - Action:** main gaming loop, controls action
	- **A - Assign Values**
		- A `Clock` object is made to control FPS
		- A variable is created that terminates gaming loop
	- **L - Loop**
		- Begin gaming loop
		- It will keep looping as long as `keepGoing == True`
	- **T - Time**
		- `clock.tick(fps)` controls how long until the loop should iterate again
	- **E - Events**
		- **event queue:** a list of events that pygame records
		- `pygame.event.get()` returns list of events that occurred; must loop over
		- `if event == pygame.QUIT` checks if user attempted to close game
	- **R - Refresh Screen**
		- update visual display
		- **blitting:** transferring blocks
			- display `Surface` objects on screen
			- display bit-by-bit
			- `screen.blit(...)` blits entities on screen
			- `(0, 0)` parameter indicates location
			- copies to memory, not to display
		- **display flipping:** the screen data is shown to the user on display
			- causes game window to update
			- `pygame.display.flip()`

## Animation

- Goal: Create small red square to move across window
- Steps
	- Create red 25x25 pixel square Surface called `box`
	- Keep track of its location using 2 variables: `box_x` and `box_y`
	- Add 5 to `box_x` to move box to right
	- `box_x` is reset to 0 if box moves beyond right edge of game window
		- makes box reappear from the left
- Use IDEA/ALTER framework

```py
import pygame
pygame.init()

# Display
screen = pygame.display.set_mode((640, 480))
pygame.display.set_caption("move a box")

# Entities
background = pygame.Surface(screen.get_size())
background.fill((255, 255, 0))

# yellow background
# make a red 25 x 25 box
box = pygame.Surface((25, 25))
box.fill((255, 0, 0))

# set up some box variables
box_x = 200
box_y = 200

# ACTION
# Assign
clock = pygame.time.Clock()
keepGoing = True

# Loop
while keepGoing:
    # Time
    clock.tick(30)
    # Events
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            keepGoing = False
    #modify box value
    box_x += 5
    #check boundaries
    if box_x > screen.get_width():
        box_x = 0
    # Refresh screen
    screen.blit(background, (0, 0))
    screen.blit(box, (box_x, box_y))
    pygame.display.flip()
```
